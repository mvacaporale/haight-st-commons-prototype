Builder note · two objectsOne house row (persistent profile) has zero-or-more listing rows (room openings). The dashboard is the hub; "Edit house info" and "Create a listing" are distinct writes. RLS scopes both to the signed-in member's house_id.
Builder note · accountsSupabase Auth with emailed magic links, no passwords and no SMS. A house applies via the "Add your House" form; an admin approves it, creates the house row, and adds 1–3 resident emails to house_members. Approval is what the Verified chip means. When someone moves out, the house (or an admin) swaps their email; nothing else changes.
Builder note · no app serverThis dashboard is one static page on GitHub Pages that talks to Supabase directly with supabase-js. RLS is the security boundary, so there's no Next.js / Node server to host. Every save to house or listing fires a webhook that rebuilds the public home page (see README).

Builder note · listing lifecycleInsert a listing row: house_id, move_in, rent, dues, term, apply_url, note, created_at, confirmed_at. Publishing is live immediately (no moderation gate in v1; keep a nullable review_status for later). A daily Supabase scheduled job (pg_cron) expires listings where now − confirmed_at > 45d, and an Edge Function emails a re-confirm nudge ~day 40 (Resend or similar). The nudge links straight back here; "Still open" just bumps confirmed_at.
